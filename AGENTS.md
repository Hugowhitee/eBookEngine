# eBookEngine agent entrypoint

This repository is the project-specific source of truth. Read `PRODUCT.md`, `ARCHITECTURE.md` and `MILESTONES.md` before making architectural decisions. For cross-project practices, load the **current** Google Drive `Digitaal/AI/AI werkinstructies/Overzicht.md`, then the smallest relevant skill closure. Do not duplicate the Drive instruction system in this repo.

Rules: source files stay immutable; proposal → accepted changes → regenerated candidate → independent validation → atomic save. Never remove a source EPUB section, image, figure, spine item or PDF page without an explicit user-approved operation. Every visible control must be functional or explain why it is disabled. Do not fabricate progress, runtime tests, a Windows installer, model performance or release status. Preserve private user books off GitHub. Avoid unneeded forks, new branches, duplicate state owners, always-on cloud services, automatic costly Actions and elaborate docs.

The GUI is native ttk/Tk as implemented, not PySide6. The design boundary is reviewable document changes, not arbitrary Acrobat-style painting. Standard unit tests: `python -m pytest -q`. Real GUI smoketest on X11 uses `xvfb-run`, but actual Windows executable verification remains a separate required gate. The manual Windows build workflow must not be described as a tested downloadable release merely because source tests pass. Keep notices required by actually distributed dependencies separately from the normal product UI; the app is an independent product.
